# 命令模式

## 摘要

命令模式，Command，把请求封装成对象，使请求的发起者和执行者解耦。命令对象可以被排队、记录、撤销、重做、延迟执行或组合执行。

它常用于菜单按钮、任务队列、事务脚本、撤销重做、宏命令、消息驱动系统。

## 解决的问题

按钮、快捷键、菜单项只知道“用户触发了某个动作”，不应该直接依赖具体业务对象。命令模式把动作包装成命令对象，触发者只调用 `execute()`。

## 核心思想

命令对象持有执行所需的接收者和参数。调用方只依赖命令接口，不关心命令内部如何执行。

## 结构与角色

- Command：命令接口，通常包含 `execute()`，可选 `undo()`。
- ConcreteCommand：具体命令，持有 Receiver。
- Receiver：真正执行业务的对象。
- Invoker：触发命令的对象，例如按钮、调度器。
- Client：创建命令并绑定接收者。

## 适用场景

- 需要把请求参数化。
- 需要撤销、重做、日志或队列。
- 触发者不应依赖业务执行者。
- 需要组合多个命令。

## 不适用场景

- 只是一次简单函数调用。
- 命令对象没有生命周期价值。
- 撤销逻辑无法可靠实现。

## 多语言实现

### Java

```java
interface Command {
    void execute();
    void undo();
}

final class Light {
    void on() {}
    void off() {}
}

final class LightOnCommand implements Command {
    private final Light light;

    LightOnCommand(Light light) {
        this.light = light;
    }

    public void execute() { light.on(); }
    public void undo() { light.off(); }
}

final class Button {
    private Command command;

    void bind(Command command) { this.command = command; }
    void click() { command.execute(); }
}
```

### C++

```cpp
struct Command { virtual void execute() = 0; virtual ~Command() = default; };
struct SaveCommand : Command { void execute() override {} };
```

### Python

```python
from typing import Protocol


class Command(Protocol):
    def execute(self) -> None:
        ...


class SaveFile:
    def __init__(self, path: str, content: str) -> None:
        self.path = path
        self.content = content

    def execute(self) -> None:
        with open(self.path, "w", encoding="utf-8") as file:
            file.write(self.content)
```

### TypeScript

```ts
interface Command {
  execute(): void;
  undo?(): void;
}

class CommandHistory {
  private stack: Command[] = [];

  run(command: Command): void {
    command.execute();
    this.stack.push(command);
  }

  undo(): void {
    this.stack.pop()?.undo?.();
  }
}
```

## 优点

- 请求发起者和执行者解耦。
- 支持撤销、队列、日志、重试。
- 容易组合宏命令。

## 代价与风险

- 类或对象数量增加。
- 撤销需要保存状态，复杂场景容易不完整。
- 命令太薄时会显得形式化。

## 常见误区

- 误区：命令模式只是把方法改成对象。
  正解：对象化后应带来排队、撤销、记录、延迟等价值。
- 误区：所有命令都必须支持撤销。
  正解：撤销是可选能力。

## 和其他模式的关系

- 备忘录可保存命令撤销所需状态。
- 职责链可以处理命令对象。
- 策略关注算法替换，命令关注请求封装和执行时机。

## 检查清单

- 请求是否需要延迟、排队或记录？
- 触发者是否需要和接收者解耦？
- 是否需要撤销或重做？
- 命令对象是否包含足够执行上下文？
