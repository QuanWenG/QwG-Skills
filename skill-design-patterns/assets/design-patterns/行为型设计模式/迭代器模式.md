# 迭代器模式

## 摘要

迭代器模式，Iterator，提供一种顺序访问聚合对象中各元素的方法，而不暴露聚合对象的内部表示。

现代语言通常内置迭代协议，例如 Java `Iterator`、Python iterator、JavaScript iterator，因此很多时候直接使用语言能力就是在使用该模式。

## 解决的问题

客户端如果直接依赖集合内部结构，例如数组、链表、树，就会和存储方式耦合。迭代器把遍历逻辑封装起来，使集合可以改变内部结构而不影响遍历方。

## 核心思想

聚合对象提供迭代器。迭代器保存遍历状态，并提供获取下一个元素的统一方式。

## 结构与角色

- Iterator：定义遍历接口。
- ConcreteIterator：保存当前位置，实现遍历逻辑。
- Aggregate：聚合对象，创建迭代器。
- ConcreteAggregate：具体集合。

## 适用场景

- 需要隐藏集合内部结构。
- 需要多种遍历方式。
- 需要同时进行多个独立遍历。
- 集合结构复杂，例如树、图、分页数据。

## 不适用场景

- 直接使用语言内置集合遍历已经足够。
- 遍历逻辑与业务强绑定，不适合抽成通用迭代器。

## 多语言实现

### Java

```java
import java.util.Iterator;
import java.util.List;

final class Team implements Iterable<String> {
    private final List<String> members;

    Team(List<String> members) {
        this.members = members;
    }

    public Iterator<String> iterator() {
        return members.iterator();
    }
}
```

### Python

```python
class Countdown:
    def __init__(self, start: int) -> None:
        self.start = start

    def __iter__(self):
        current = self.start
        while current > 0:
            yield current
            current -= 1
```

### JavaScript

```js

```

### TypeScript

```ts
class NumberRange implements Iterable<number> {
  constructor(private readonly start: number, private readonly end: number) {}

  *[Symbol.iterator](): Iterator<number> {
    for (let i = this.start; i <= this.end; i += 1) {
      yield i;
    }
  }
}
```

## 优点

- 隐藏集合内部结构。
- 遍历算法可独立变化。
- 支持多个遍历器同时存在。

## 代价与风险

- 简单集合中手写迭代器没有必要。
- 迭代期间集合被修改可能产生一致性问题。
- 复杂迭代器需要处理资源释放。

## 常见误区

- 误区：有 `for` 循环就不是迭代器模式。
  正解：很多 `for` 循环背后正是语言迭代协议。
- 误区：迭代器只能顺序遍历数组。
  正解：树、分页接口、数据库游标都可以抽象为迭代器。

## 和其他模式的关系

- 组合模式的树结构常配合迭代器遍历。
- 访问者关注对元素执行操作，迭代器关注如何访问元素。
- 生成器是许多语言中实现迭代器的简洁方式。

## 检查清单

- 是否需要隐藏集合内部结构？
- 是否需要多种遍历方式？
- 遍历期间集合修改如何处理？
- 是否可以直接使用语言内置迭代协议？
