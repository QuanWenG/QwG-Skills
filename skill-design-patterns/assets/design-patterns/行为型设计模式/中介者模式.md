# 中介者模式

## 摘要

中介者模式，Mediator，用一个中介对象封装一组对象之间的交互，使对象之间不直接相互引用，从而降低网状耦合。

它适合 UI 控件联动、聊天室、工作流协调、模块间复杂协作。

## 解决的问题

多个对象彼此直接调用时，关系会变成网状。任意一个对象变化都可能影响多个对象。中介者把交互规则集中起来，对象只和中介者通信。

## 核心思想

参与者不直接通知其他参与者，而是通知中介者。中介者根据规则协调其他对象。

## 结构与角色

- Mediator：中介者接口。
- ConcreteMediator：具体协调逻辑。
- Colleague：参与者对象，持有中介者。

## 适用场景

- 多个对象交互复杂。
- 对象之间存在大量双向引用。
- 协调规则需要集中管理。
- UI 表单控件状态互相影响。

## 不适用场景

- 对象关系简单，直接调用更清楚。
- 中介者会变成上帝对象。
- 协调逻辑本应属于某个领域对象。

## 多语言实现

### Java

```java
interface DialogMediator {
    void changed(String component);
}

final class LoginDialog implements DialogMediator {
    private boolean usernameFilled;
    private boolean passwordFilled;

    public void changed(String component) {
        boolean canSubmit = usernameFilled && passwordFilled;
        System.out.println("submit enabled: " + canSubmit);
    }

    void usernameChanged(String value) {
        usernameFilled = !value.isBlank();
        changed("username");
    }

    void passwordChanged(String value) {
        passwordFilled = !value.isBlank();
        changed("password");
    }
}
```

### TypeScript

```ts
class FormMediator {
  private valid = { name: false, email: false };

  update(field: "name" | "email", value: string): boolean {
    this.valid[field] = value.trim().length > 0;
    return this.valid.name && this.valid.email;
  }
}
```

## 优点

- 减少对象间直接依赖。
- 交互规则集中。
- 单个参与者更容易复用。

## 代价与风险

- 中介者容易膨胀。
- 交互逻辑过度集中后难以维护。
- 可能掩盖领域模型本该表达的关系。

## 常见误区

- 误区：所有对象通信都应该经过中介者。
  正解：只有网状依赖复杂时才值得引入。
- 误区：中介者等于外观。
  正解：外观简化子系统入口，中介者协调对象之间的交互。

## 和其他模式的关系

- 观察者通过发布订阅通知，中介者集中编排交互。
- 外观面向客户端简化调用，中介者面向内部对象协调。
- 命令可作为中介者调度的动作单元。

## 检查清单

- 对象关系是否已经变成网状？
- 交互规则是否需要集中维护？
- 中介者是否会过度膨胀？
- 参与者是否仍保持清晰职责？
