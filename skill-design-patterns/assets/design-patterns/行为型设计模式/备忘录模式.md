# 备忘录模式

## 摘要

备忘录模式，Memento，在不暴露对象内部实现的前提下捕获对象状态，并允许之后恢复到该状态。

它常用于撤销、快照、草稿保存、事务回滚、游戏存档。

## 解决的问题

对象内部状态可能复杂，外部如果直接读取和保存这些字段，会破坏封装。备忘录让对象自己创建状态快照，外部只负责保存快照，不理解快照内容。

## 核心思想

原发器创建备忘录保存当前状态；负责人保存备忘录；需要恢复时，原发器从备忘录恢复。

## 结构与角色

- Originator：原发器，拥有内部状态，能创建和恢复备忘录。
- Memento：备忘录，保存状态快照。
- Caretaker：负责人，只保存备忘录，不解析内容。

## 适用场景

- 需要撤销、重做。
- 需要快照和恢复。
- 状态应保持封装。
- 状态复制成本可接受。

## 不适用场景

- 状态巨大，频繁快照成本过高。
- 状态包含外部资源，无法可靠恢复。
- 只需要简单命令反操作，命令模式可能足够。

## 多语言实现

### Java

```java
record EditorMemento(String text, int cursor) {}

final class Editor {
    private String text = "";
    private int cursor = 0;

    void type(String value) {
        text += value;
        cursor = text.length();
    }

    EditorMemento save() {
        return new EditorMemento(text, cursor);
    }

    void restore(EditorMemento memento) {
        this.text = memento.text();
        this.cursor = memento.cursor();
    }
}
```

### C++

```cpp
struct Snapshot { std::string text; };

```

### Python

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Memento:
    text: str


class Editor:
    def __init__(self) -> None:
        self._text = ""

    def type(self, value: str) -> None:
        self._text += value

    def save(self) -> Memento:
        return Memento(self._text)

    def restore(self, snapshot: Memento) -> None:
        self._text = snapshot.text
```

### JavaScript

```js
class Editor { constructor(){ this.text = ""; } save(){ return { text: this.text }; } restore(s){ this.text = s.text; } }
```

### TypeScript

```ts
type EditorSnapshot = Readonly<{ text: string; cursor: number }>;

class Editor {
  private text = "";
  private cursor = 0;

  save(): EditorSnapshot {
    return { text: this.text, cursor: this.cursor };
  }

  restore(snapshot: EditorSnapshot): void {
    this.text = snapshot.text;
    this.cursor = snapshot.cursor;
  }
}
```

## 优点

- 保持封装。
- 支持撤销和恢复。
- 快照逻辑集中在对象自身。

## 代价与风险

- 快照可能占用大量内存。
- 深拷贝边界需要明确。
- 频繁保存可能影响性能。

## 常见误区

- 误区：备忘录就是直接暴露所有字段。
  正解：外部应保存快照，但不依赖内部字段语义。
- 误区：备忘录必须保存完整状态。
  正解：也可以保存增量，但实现更复杂。

## 和其他模式的关系

- 命令模式的撤销可用备忘录保存执行前状态。
- 原型模式关注复制对象，备忘录关注状态快照和恢复。
- 迭代器也可能用备忘录保存遍历位置。

## 检查清单

- 是否需要恢复历史状态？
- 快照是否会破坏封装？
- 状态大小和保存频率是否可接受？
- 是否需要完整快照还是增量快照？
