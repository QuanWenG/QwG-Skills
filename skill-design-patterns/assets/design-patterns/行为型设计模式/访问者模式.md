# 访问者模式

## 摘要

访问者模式，Visitor，把作用于某对象结构中各元素的操作封装成独立访问者，使你可以在不修改元素类的前提下增加新操作。

它适合对象结构稳定、操作经常增加的场景，例如 AST 编译器、报表导出、复杂对象树统计。

## 解决的问题

一个对象结构中有多种元素，例如 `Circle`、`Rectangle`、`Group`。如果不断新增导出 JSON、计算面积、生成 XML 等操作，每个元素类都要反复修改。访问者把操作移到访问者对象中。

## 核心思想

元素接受访问者 `accept(visitor)`，再调用访问者针对自己类型的重载方法。这样通过双分派把“元素类型 + 操作类型”分离。

## 结构与角色

- Visitor：访问者接口，为每种元素声明访问方法。
- ConcreteVisitor：具体操作。
- Element：元素接口，定义 `accept`。
- ConcreteElement：具体元素，调用对应访问方法。
- ObjectStructure：元素集合或对象树。

## 适用场景

- 对象结构稳定。
- 经常新增跨元素操作。
- 操作需要访问多个不同元素类型。
- 编译器 AST、文档对象树、组合树。

## 不适用场景

- 元素类型经常增加。
- 访问者需要破坏封装访问大量内部状态。
- 语言模式匹配或代数数据类型已经更简单。

## 多语言实现

### Java

```java
interface Shape {
    void accept(ShapeVisitor visitor);
}

final class Circle implements Shape {
    final int radius;

    Circle(int radius) {
        this.radius = radius;
    }

    public void accept(ShapeVisitor visitor) {
        visitor.visitCircle(this);
    }
}

final class Rectangle implements Shape {
    final int width;
    final int height;

    Rectangle(int width, int height) {
        this.width = width;
        this.height = height;
    }

    public void accept(ShapeVisitor visitor) {
        visitor.visitRectangle(this);
    }
}

interface ShapeVisitor {
    void visitCircle(Circle circle);
    void visitRectangle(Rectangle rectangle);
}
```

### Python

```python
from functools import singledispatchmethod


class Circle:
    def __init__(self, radius: int) -> None:
        self.radius = radius


class Rectangle:
    def __init__(self, width: int, height: int) -> None:
        self.width = width
        self.height = height


class AreaVisitor:
    @singledispatchmethod
    def area(self, shape) -> int:
        raise NotImplementedError

    @area.register
    def _(self, shape: Circle) -> int:
        return 3 * shape.radius * shape.radius

    @area.register
    def _(self, shape: Rectangle) -> int:
        return shape.width * shape.height
```

### JavaScript

```js
class Circle { accept(visitor){ visitor.visitCircle(this); } }
```

### TypeScript

```ts
interface Visitor {
  visitCircle(circle: Circle): void;
  visitRectangle(rectangle: Rectangle): void;
}

interface Shape {
  accept(visitor: Visitor): void;
}

class Circle implements Shape {
  constructor(readonly radius: number) {}
  accept(visitor: Visitor): void {
    visitor.visitCircle(this);
  }
}

class Rectangle implements Shape {
  constructor(readonly width: number, readonly height: number) {}
  accept(visitor: Visitor): void {
    visitor.visitRectangle(this);
  }
}
```

## 优点

- 新增操作不必修改元素类。
- 跨元素操作集中。
- 适合稳定对象结构上的多种分析和导出。

## 代价与风险

- 新增元素类型会修改所有访问者。
- 访问者可能需要元素暴露内部细节。
- 双分派结构理解成本较高。

## 常见误区

- 误区：访问者适合频繁新增元素。
  正解：访问者适合元素稳定、操作多变。
- 误区：访问者只是遍历。
  正解：遍历可由迭代器或对象结构负责，访问者关注操作分派。

## 和其他模式的关系

- 组合模式常提供对象树，访问者为树增加操作。
- 迭代器负责访问顺序，访问者负责对元素执行操作。
- 解释器的语法树可用访问者增加求值、打印、类型检查等操作。

## 检查清单

- 元素类型是否稳定？
- 是否经常新增跨元素操作？
- 新增元素时修改所有访问者的成本是否可接受？
- 是否可以用模式匹配或简单函数替代？
