# 观察者模式

## 摘要

观察者模式，Observer，定义对象之间的一对多依赖。当主题对象状态变化时，所有观察者都会收到通知并自动更新。

它常用于事件系统、消息订阅、UI 数据绑定、领域事件、异步通知。

## 解决的问题

一个对象变化后需要通知多个对象。如果主题直接调用每个依赖对象，会强耦合具体观察者。观察者模式让主题只维护观察者接口列表。

## 核心思想

观察者订阅主题。主题状态变化时调用观察者的通知方法。观察者可以注册和取消注册。

## 结构与角色

- Subject：主题，维护观察者列表。
- Observer：观察者接口。
- ConcreteSubject：具体主题，发布事件。
- ConcreteObserver：具体观察者，响应事件。

## 适用场景

- 一个对象变化需要通知多个对象。
- 订阅者集合运行时变化。
- 事件发布者不应依赖订阅者。
- UI、消息、领域事件。

## 不适用场景

- 通知顺序强依赖且复杂。
- 需要强一致事务语义。
- 订阅关系难以管理导致内存泄漏。

## 多语言实现

### Java

```java
import java.util.ArrayList;
import java.util.List;

interface Observer {
    void update(String event);
}

final class EventSource {
    private final List<Observer> observers = new ArrayList<>();

    void subscribe(Observer observer) { observers.add(observer); }
    void unsubscribe(Observer observer) { observers.remove(observer); }

    void publish(String event) {
        for (Observer observer : List.copyOf(observers)) {
            observer.update(event);
        }
    }
}
```

### C++

```cpp
struct Observer { virtual void update(int)=0; virtual ~Observer()=default; };

```

### Python

```python
from collections.abc import Callable


class EventBus:
    def __init__(self) -> None:
        self._handlers: list[Callable[[str], None]] = []

    def subscribe(self, handler: Callable[[str], None]) -> None:
        self._handlers.append(handler)

    def publish(self, event: str) -> None:
        for handler in list(self._handlers):
            handler(event)
```

### JavaScript

```js
class Subject { constructor(){ this.listeners = new Set(); } subscribe(fn){ this.listeners.add(fn); } notify(v){ this.listeners.forEach(fn => fn(v)); } }
```

### TypeScript

```ts
type Listener<T> = (event: T) => void;

class Subject<T> {
  private listeners = new Set<Listener<T>>();

  subscribe(listener: Listener<T>): () => void {
    this.listeners.add(listener);
    return () => this.listeners.delete(listener);
  }

  notify(event: T): void {
    for (const listener of this.listeners) listener(event);
  }
}
```

## 优点

- 发布者和订阅者解耦。
- 支持动态订阅。
- 适合事件驱动架构。

## 代价与风险

- 通知链可能难追踪。
- 观察者异常处理需要明确。
- 忘记取消订阅可能造成泄漏。
- 异步事件可能带来一致性问题。

## 常见误区

- 误区：观察者等于消息队列。
  正解：消息队列是跨进程或异步基础设施，观察者是对象协作模式。
- 误区：观察者通知一定异步。
  正解：可以同步也可以异步，取决于实现。

## 和其他模式的关系

- 中介者集中协调交互，观察者分发状态变化通知。
- 命令可作为事件处理动作。
- MVC/MVVM 中模型变化通知视图常用观察者思想。

## 检查清单

- 发布者是否不应知道具体订阅者？
- 订阅者是否需要动态增减？
- 通知顺序、异常和线程模型是否明确？
- 是否有取消订阅机制？
