# 代理模式

## 摘要

代理模式为目标对象提供替身或占位符，由代理控制对目标对象的访问，并可在调用前后加入额外逻辑。

常见类型包括静态代理、动态代理、远程代理、虚拟代理、保护代理、缓存代理和 AOP 代理。

## 解决的问题

客户端直接访问目标对象时，权限校验、日志、事务、缓存、延迟加载、远程调用等横切逻辑容易散落。代理把访问控制集中在代理对象中，并保持与目标对象相同的接口。

## 核心思想

代理和真实对象实现同一接口。客户端调用代理，代理决定是否、何时、如何调用真实对象。

## 结构与角色

- Subject：公共接口。
- RealSubject：真实对象。
- Proxy：代理对象，持有或创建 RealSubject。
- Client：通过 Subject 使用代理。

## 适用场景

- 权限控制。
- 日志、监控、事务。
- 懒加载昂贵对象。
- RPC 或远程服务本地化。
- 缓存结果。

## 不适用场景

- 额外逻辑与访问控制无关，应该放在业务对象内。
- 代理层让调用链难以追踪。
- 需要改变接口，此时适配器更合适。

## 多语言实现

### Java

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

interface UserService {
    void create(String name);
}

final class LogHandler implements InvocationHandler {
    private final Object target;

    LogHandler(Object target) {
        this.target = target;
    }

    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("before " + method.getName());
        Object result = method.invoke(target, args);
        System.out.println("after " + method.getName());
        return result;
    }

    static UserService wrap(UserService target) {
        return (UserService) Proxy.newProxyInstance(
            target.getClass().getClassLoader(),
            new Class<?>[] { UserService.class },
            new LogHandler(target)
        );
    }
}
```

### C++

```cpp
struct Service { virtual void call() = 0; virtual ~Service() = default; };
struct Proxy : Service { Service& target; Proxy(Service& s): target(s) {} void call() override { target.call(); } };
```

### Python

```python
class Image:
    def display(self) -> None:
        pass


class LazyImageProxy:
    def __init__(self, path: str) -> None:
        self._path = path
        self._image: Image | None = None

    def display(self) -> None:
        if self._image is None:
            self._image = Image()
        self._image.display()
```

### TypeScript

```ts
interface Repository {
  find(id: string): Promise<string>;
}

class CacheProxy implements Repository {
  private cache = new Map<string, string>();

  constructor(private readonly target: Repository) {}

  async find(id: string): Promise<string> {
    const cached = this.cache.get(id);
    if (cached) return cached;
    const value = await this.target.find(id);
    this.cache.set(id, value);
    return value;
  }
}
```

## 优点

- 横切逻辑集中。
- 客户端无感使用同一接口。
- 可控制目标对象生命周期和访问权限。

## 代价与风险

- 调用链增加。
- 动态代理调试更难。
- 代理过多会隐藏真实执行路径。

## 常见误区

- 误区：代理和装饰器一样。
  正解：二者都包装对象，但代理强调访问控制，装饰强调功能增强。
- 误区：动态代理不用关心接口契约。
  正解：代理必须保持目标接口的行为契约。

## 和其他模式的关系

- 装饰器增加职责，代理控制访问。
- 适配器改变接口，代理保持接口。
- 外观提供高层入口，代理通常对应单个目标对象。

## 检查清单

- 是否需要在访问前后加入控制逻辑？
- 代理是否保持接口契约？
- 横切逻辑是否应该由 AOP 或中间件承担？
- 调试和异常栈是否仍可接受？
