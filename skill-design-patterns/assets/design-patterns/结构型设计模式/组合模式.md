# 组合模式

## 摘要

组合模式把对象组织成树形结构，使客户端可以一致地处理单个对象和对象组合。

文件和文件夹、组织架构、菜单树、表达式树、UI 组件树都是常见例子。

## 解决的问题

客户端如果分别处理叶子节点和容器节点，会出现大量类型判断。组合模式让二者实现共同组件接口，客户端可以递归调用统一操作。

## 核心思想

叶子和组合节点都实现 Component。组合节点内部持有子 Component 列表。客户端面对 Component 编程。

## 结构与角色

- Component：统一抽象。
- Leaf：叶子对象，没有子节点。
- Composite：组合对象，包含子节点。
- Client：统一处理 Component。

## 适用场景

- 数据天然是树结构。
- 希望统一处理整体和部分。
- 操作可以递归传播。

## 不适用场景

- 对象关系不是树。
- 叶子和容器操作差异非常大。
- 需要严格禁止某些节点拥有子节点且不希望运行时异常。

## 多语言实现

### Java

```java
interface Node {
    int size();
}

final class FileNode implements Node {
    private final int bytes;

    FileNode(int bytes) { this.bytes = bytes; }

    public int size() { return bytes; }
}

final class FolderNode implements Node {
    private final java.util.List<Node> children = new java.util.ArrayList<>();

    void add(Node node) { children.add(node); }

    public int size() {
        return children.stream().mapToInt(Node::size).sum();
    }
}
```

### Python

```python
class Component:
    def size(self) -> int:
        raise NotImplementedError


class File(Component):
    def __init__(self, size: int) -> None:
        self._size = size

    def size(self) -> int:
        return self._size


class Folder(Component):
    def __init__(self) -> None:
        self._children: list[Component] = []

    def add(self, child: Component) -> None:
        self._children.append(child)

    def size(self) -> int:
        return sum(child.size() for child in self._children)
```

### JavaScript


### TypeScript

```ts
interface MenuItem {
  render(): string;
}

class LinkItem implements MenuItem {
  constructor(private readonly text: string) {}
  render(): string { return this.text; }
}

class MenuGroup implements MenuItem {
  private children: MenuItem[] = [];
  add(item: MenuItem): void { this.children.push(item); }
  render(): string { return this.children.map(c => c.render()).join("\n"); }
}
```

## 优点

- 客户端代码简单。
- 树形递归表达自然。
- 新增节点类型容易。

## 代价与风险

- 统一接口可能让叶子暴露无意义操作。
- 递归层级过深要注意性能和栈深度。
- 父子关系和循环引用需要管理。

## 常见误区

- 误区：组合模式等于组合复用原则。
  正解：组合模式是树结构模式，CRP 是优先组合而非继承的原则。
- 误区：所有容器都适合组合模式。
  正解：关键是整体和部分能否统一处理。

## 和其他模式的关系

- 解释器常用组合表示 AST。
- 装饰器也实现相同接口，但它是单层包装，不是树形整体部分。
- 访问者可为组合树增加操作。

## 检查清单

- 是否是整体-部分树结构？
- 客户端是否需要统一处理叶子和组合？
- 递归操作是否清晰？
- 叶子是否被迫实现无意义方法？
