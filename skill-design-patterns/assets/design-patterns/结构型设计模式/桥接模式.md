# 桥接模式

## 摘要

桥接模式将抽象部分与实现部分分离，使二者可以独立变化。它适合处理两个或多个变化维度同时扩展导致的类爆炸。

原始笔记中的“消息类型 + 发送方式”例子很典型：紧急消息、普通消息、营销消息是一条变化轴；邮件、短信、推送是另一条变化轴。

## 解决的问题

如果用继承组合所有维度，会出现 `UrgentEmailMessage`、`UrgentSmsMessage`、`MarketingEmailMessage` 等大量类。桥接用组合连接两个维度，避免笛卡尔积式继承。

## 核心思想

抽象对象持有实现接口。抽象层负责高层语义，实现层负责底层动作。新增抽象类型和新增实现类型互不影响。

## 结构与角色

- Abstraction：抽象层，例如 Message。
- RefinedAbstraction：扩展抽象，例如 UrgentMessage。
- Implementor：实现接口，例如 MessageSender。
- ConcreteImplementor：具体实现，例如 EmailSender。

## 适用场景

- 有多个独立变化维度。
- 想避免继承层级爆炸。
- 抽象和实现都需要独立扩展。
- 运行时需要组合不同实现。

## 不适用场景

- 只有一个变化维度。
- 简单策略注入已经足够。
- 抽象和实现并不独立变化。

## 多语言实现

### Java

```java
interface MessageSender {
    void send(String message);
}

final class EmailSender implements MessageSender {
    public void send(String message) {}
}

abstract class Message {
    protected final MessageSender sender;

    Message(MessageSender sender) {
        this.sender = sender;
    }

    abstract void send(String content);
}

final class UrgentMessage extends Message {
    UrgentMessage(MessageSender sender) {
        super(sender);
    }

    void send(String content) {
        sender.send("[urgent] " + content);
    }
}
```

### C++

```cpp
struct Renderer { virtual void draw() = 0; virtual ~Renderer() = default; };
struct Shape { Renderer& r; Shape(Renderer& r): r(r) {} void render(){ r.draw(); } };
```

```go
type Renderer interface{ Draw() }
```

### Python

```python
class Sender:
    def send(self, text: str) -> None:
        raise NotImplementedError


class SmsSender(Sender):
    def send(self, text: str) -> None:
        pass


class MarketingMessage:
    def __init__(self, sender: Sender) -> None:
        self._sender = sender

    def send(self, text: str) -> None:
        self._sender.send(f"[ad] {text}")
```

### JavaScript

```js
class Shape { constructor(renderer){ this.renderer = renderer; } render(){ this.renderer.draw(); } }
```

### TypeScript

```ts
interface Renderer {
  drawCircle(radius: number): void;
}

class SvgRenderer implements Renderer {
  drawCircle(radius: number): void {}
}

class Circle {
  constructor(private readonly renderer: Renderer, private readonly radius: number) {}

  draw(): void {
    this.renderer.drawCircle(this.radius);
  }
}
```

## 优点

- 避免类爆炸。
- 两个维度独立扩展。
- 运行时组合灵活。

## 代价与风险

- 需要提前识别变化维度。
- 抽象层和实现层命名不清会难理解。
- 对简单场景显得过度设计。

## 常见误区

- 误区：桥接就是普通组合。
  正解：桥接强调抽象和实现两个维度的独立演化。
- 误区：有接口注入就是桥接。
  正解：还要看是否存在两个变化轴。

## 和其他模式的关系

- 策略模式通常只有一个算法变化点；桥接关注两个层次独立变化。
- 适配器常用于事后兼容，桥接是事前设计。
- CRP 是桥接的基础。

## 检查清单

- 是否存在两个独立变化维度？
- 是否正在出现组合类爆炸？
- 抽象层是否只关心高层语义？
- 实现层是否可以独立替换？
