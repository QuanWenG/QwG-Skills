# 建造者模式

## 摘要

建造者模式把复杂对象的构建过程与对象表示分离，使同样的构建过程可以创建不同表示。现代开发中，Builder 也常用于解决构造参数过多、可选参数多、对象不可变构造不便的问题。

原始笔记中 `Student.builder().id(...).age(...).build()` 是典型链式 Builder。

## 解决的问题

当构造函数参数很多时，调用方很难知道每个参数的含义，也容易传错顺序。大量重载构造函数也会变得难维护。Builder 让调用方通过有名字的步骤逐步配置对象。

## 核心思想

把待构建对象的参数暂存在 Builder 中，调用 `build()` 时统一校验并创建目标对象。复杂场景还可以引入 Director 固定构建顺序。

## 结构与角色

- Product：最终对象。
- Builder：定义构建步骤。
- ConcreteBuilder：保存构建状态并生成产品。
- Director：可选，封装固定构建流程。

## 适用场景

- 构造参数多，可选项多。
- 需要创建不可变对象。
- 构建过程需要校验。
- 同一流程创建不同表示。

## 不适用场景

- 对象只有少量必填参数。
- 构建没有中间状态和校验。
- Builder 只是机械复制 setter。

## 多语言实现

### Java

```java
public final class Student {
    private final int id;
    private final String name;
    private final int age;

    private Student(Builder builder) {
        this.id = builder.id;
        this.name = builder.name;
        this.age = builder.age;
    }

    public static Builder builder() {
        return new Builder();
    }

    public static final class Builder {
        private int id;
        private String name;
        private int age;

        public Builder id(int id) { this.id = id; return this; }
        public Builder name(String name) { this.name = name; return this; }
        public Builder age(int age) { this.age = age; return this; }

        public Student build() {
            if (name == null || name.isBlank()) {
                throw new IllegalStateException("name is required");
            }
            return new Student(this);
        }
    }
}
```

### Python

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Student:
    id: int
    name: str
    age: int = 18


class StudentBuilder:
    def __init__(self) -> None:
        self._id = 0
        self._name = ""
        self._age = 18

    def id(self, value: int) -> "StudentBuilder":
        self._id = value
        return self

    def name(self, value: str) -> "StudentBuilder":
        self._name = value
        return self

    def build(self) -> Student:
        if not self._name:
            raise ValueError("name is required")
        return Student(self._id, self._name, self._age)
```

### TypeScript

```ts
class Student {
  private constructor(
    readonly id: number,
    readonly name: string,
    readonly age: number,
  ) {}

  static builder() {
    return new StudentBuilder();
  }
}

class StudentBuilder {
  private idValue = 0;
  private nameValue = "";
  private ageValue = 18;

  id(value: number): this { this.idValue = value; return this; }
  name(value: string): this { this.nameValue = value; return this; }
  age(value: number): this { this.ageValue = value; return this; }

  build(): Student {
    if (!this.nameValue) throw new Error("name is required");
    return new (Student as any)(this.idValue, this.nameValue, this.ageValue);
  }
}
```

## 优点

- 调用可读性高。
- 支持不可变对象。
- 构建校验集中。
- 避免构造函数参数爆炸。

## 代价与风险

- 类数量增加。
- 简单对象使用 Builder 会显得啰嗦。
- Builder 可变，复用同一个 Builder 时要注意状态残留。

## 常见误区

- 误区：所有多参数对象都必须 Builder。
  正解：语言支持命名参数或对象参数时，可以更简单。
- 误区：Builder 必须有 Director。
  正解：现代链式 Builder 经常不需要 Director。

## 和其他模式的关系

- 抽象工厂创建产品族，Builder 创建复杂单个对象。
- 模板方法可固定构建流程。
- Fluent Interface 常用于 Builder API 风格。

## 检查清单

- 构造参数是否多且可选？
- 是否需要不可变对象？
- 是否需要构建时校验？
- 对象参数或命名参数是否已经足够？
