# 原型模式

## 摘要

原型模式通过复制已有对象来创建新对象，而不是从零调用构造函数。它适合对象创建成本高、初始状态复杂、同类对象差异较小的场景。

原始笔记中浅克隆和深克隆的区分是核心：浅克隆共享引用对象，深克隆递归复制引用对象。

## 解决的问题

某些对象初始化需要读取配置、构建复杂状态或调用昂贵资源。每次从零创建成本高。如果新对象与已有对象只有少量差异，可以复制原型再调整。

## 核心思想

对象提供复制能力，客户端不依赖具体构造过程。复制时必须明确哪些状态共享、哪些状态独立。

## 结构与角色

- Prototype：声明 clone/copy 方法。
- ConcretePrototype：实现复制逻辑。
- Client：复制原型并按需修改。

## 适用场景

- 创建成本高。
- 对象状态复杂。
- 需要运行时动态创建相似对象。
- 希望避免客户端知道构造细节。

## 不适用场景

- 对象很简单，直接构造更清楚。
- 对象包含不可复制资源，如打开的文件句柄、锁、线程。
- 深拷贝边界难以定义。

## 多语言实现

### Java

```java
import java.util.ArrayList;
import java.util.List;

final class Document {
    private final String title;
    private final List<String> tags;

    Document(String title, List<String> tags) {
        this.title = title;
        this.tags = new ArrayList<>(tags);
    }

    Document copyWithTitle(String newTitle) {
        return new Document(newTitle, tags);
    }
}
```

### C++

```cpp
struct Document { std::string title; std::vector<std::string> tags; Document clone() const { return *this; } };
```

### Go

```go
type Document struct{ Title string; Tags []string }
func (d Document) Clone() Document { tags := append([]string{}, d.Tags...); return Document{d.Title, tags} }
```

### Kotlin

```kotlin
data class Document(val title: String, val tags: List<String>)
val copy = Document("a", listOf("x")).copy(title = "b")
```

### C#

```csharp
public record Document(string Title, string[] Tags);
var copy = doc with { Title = "new" };
```

### Python

```python
from copy import copy, deepcopy

profile = {"name": "A", "roles": ["admin"]}

shallow = copy(profile)
deep = deepcopy(profile)

shallow["roles"].append("user")
assert profile["roles"] == ["admin", "user"]
assert deep["roles"] == ["admin"]
```

### JavaScript

```js
const cloneDocument = d => ({ ...d, tags: [...d.tags] });
```

### TypeScript

```ts
type UserProfile = {
  name: string;
  roles: string[];
};

function cloneProfile(profile: UserProfile): UserProfile {
  return {
    ...profile,
    roles: [...profile.roles],
  };
}
```

## 优点

- 避免重复昂贵初始化。
- 隐藏构造细节。
- 运行时可以复制动态配置出的对象。

## 代价与风险

- 深拷贝实现复杂。
- 共享可变引用容易产生隐蔽 bug。
- 对外部资源复制语义不清晰。

## 常见误区

- 误区：浅拷贝一定错误。
  正解：不可变对象或有意共享的状态可以浅拷贝。
- 误区：深拷贝一定安全。
  正解：深拷贝可能昂贵，也可能复制了不该复制的资源。
- 误区：Java `Cloneable` 是最佳实践。
  正解：很多 Java 项目更偏好 copy constructor、静态工厂或序列化方案。

## 和其他模式的关系

- 原型和工厂都隐藏创建细节；原型基于复制，工厂基于构造。
- 享元共享对象，原型复制对象，二者方向相反。
- 建造者适合逐步配置，原型适合从已有配置复制。

## 检查清单

- 对象创建是否昂贵？
- 新对象和旧对象是否高度相似？
- 哪些字段应该共享，哪些应该复制？
- 是否包含不可复制资源？
